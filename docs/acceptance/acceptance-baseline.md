## QA/UAT operating rules

- Each requirement must have exact approved scope and corresponding test cases. A code may require multiple cases by page/form/locale/viewport/OS/browser, especially AC-05 combined filters and AC-07 form validation.
- For each test store: requirement ID, acceptance code, test ID, URL, exact Git SHA/deploy ID, state/data fixture, device/viewport/locale, steps, expected/actual, evidence, reviewer/time, Pass/Fail/Blocked/Not Run. A category is Pass only when **all required** cases pass on the assessed version.
- A draft AC not commercially in scope is Pending Scope, not automatically Not Applicable. An outstanding implementation decision is Blocked when it prevents running the relevant acceptance.
- Demos with synthetic data do not certify production backend, CMS, API, access control or real CV handling.
- Use approved real-device matrix, reviewable screenshots and interaction recordings. Automated axe/build success alone is not proof of full WCAG compliance.
- Do not mark any production checklist as signed off without the customer/PO acceptance document or approved GitHub decision.
- Source and acceptance changes MUST be committed and pushed to GitHub with PR and versioning. Private raw source material only in authorized PRIVATE repository.
